## 3. Core Coding Principles (The "Gospel")

### A. Routing & URL State (TanStack Router)
* **Source of Truth:** The URL is the primary source of truth.
* **Search Params:** Use `zod` validators for search params. Store UI state in the URL (e.g., `?tab=analysis&zoom=2x`) so links are shareable.
* **Type Safety:** Never use "magic strings" for navigation. Use the typed `Link` component or `useNavigate` hook generated by the router.

### B. Data Fetching (TanStack Query)
* **No `useEffect` for Data:** Never use `useEffect` to fetch data. Always use `useQuery`.
* **Custom Hooks:** Wrap all API calls in custom hooks (e.g., `usePatientData(id)`). Do not call `fetch` directly in UI components.
* **Keys:** Use "Factory" pattern for Query Keys (e.g., `const patientKeys = { all: ['patients'], detail: (id) => [...patientKeys.all, id] }`).

### C. UI & Styling (Shadcn + Tailwind)
* **Ownership:** We own the UI code. If we need a custom Button, we edit `components/ui/button.tsx`, we do not install a new library.
* **Composition:** Build complex interfaces by composing small Shadcn primitives (Card, Dialog, ScrollArea).
* **Responsiveness:** Mobile-first Tailwind classes (`w-full md:w-1/2`).

### D. Interactive Logic
* **Performance:** For high-frequency updates , avoid React State renders. Use `refs` to manipulate Canvas .
* **Logic Separation:** Keep complex business logic (e.g., processing algorithms) in pure TypeScript files (`src/lib/audio/`), separate from React Components.

## 5. Agent Instructions (Meta-Prompt)

When generating code for this project:

1. **Always** output TypeScript.
2. **Always** use functional components.
3. **Prefer** `const` over `function` for component definitions.
4. If creating a new feature, look for existing Shadcn components to reuse first.
5. If logic involves async data, automatically scaffold a TanStack Query hook.
